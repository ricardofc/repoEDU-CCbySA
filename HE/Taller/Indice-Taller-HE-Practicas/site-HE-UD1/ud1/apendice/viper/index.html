    Automatización · VIPER (Packer + VirtualBox)

    ➡️ Práctica correspondente: Simulación de Ataques con VIPER

    Este documento monta o escenario completo da práctica Simulación de Ataques con VIPER de principio a fin, usando Packer e imaxes oficiais. Constrúe tres máquinas virtuais autoxestionadas (sen intervención manual na instalación) e déixaas listas e cableadas en VirtualBox. Todo o código do laboratorio está publicado no repositorio ricardofc/viper-he.lab, así que só hai que clonalo e executar os seus scripts.

    Contido do repositorio

    Todos os ficheiros do laboratorio (templates *.pkr.hcl, preseed.cfg, Autounattend.xml, configure.sh/configure.ps1, build-all.sh e import.sh) están versionados e documentados en ricardofc/viper-he.lab; o seu README.md resume o escenario, as credenciais e o fluxo completo. Para este taller só precisas clonalo e executar os scripts tal cal.

    Oficial VIPER: viperrtp.com · GitHub (FunnyWolf/Viper) · Packer: packer.io

    Só en laboratorio illado

    A VM-3 (Windows 11) ten o firewall e o UAC desactivados, Defender neutralizado e permite admin remoto con contas locais; as Debian reducen tamén a seguridade. Úsase unicamente nunha rede interna de VirtualBox illada. Nunca expoñas estas máquinas a Internet.

    Escenario e credenciais

    Tres VMs nunha rede interna de VirtualBox chamada viper-lan (192.168.120.0/24). As dúas Debian levan ademais NAT no adaptador 1 (saída a Internet), igual que na práctica.

    VM Rol SO (oficial) IP interna Acceso
    VM-1 Atacante / C2 (VIPER) Debian 13 + XFCE 192.168.120.100 escritorio viper / abc123. (autologin) · root / abc123. · Dashboard https://192.168.120.100:60000 (root/abc123.)
    VM-2 Vítima (payload) Debian 13 192.168.120.101 losada / abc123. · root / abc123.
    VM-3 Vítima (mov. lateral) Windows 11 Enterprise Eval 192.168.120.102 usuario / abc123. (admin local)

    Requisitos

    • VirtualBox 7.1+, Packer e git no host (a instalación de Packer e git está no Paso 1).
    • Espazo e RAM dabondo para executar as tres VMs á vez (a VM-1 con VIPER en Docker é a máis esixente).

    Paso 1 — Instalar Packer e git (no host Debian)

    Packer distribúese dende o repositorio oficial de HashiCorp:

    # Repositorio oficial de HashiCorp
apt update && apt -y install gpg wget git
wget -O- https://apt.releases.hashicorp.com/gpg | gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" > /etc/apt/sources.list.d/hashicorp.list

# Instalación de Packer
apt update && apt -y install packer

    Paso 2 — Clonar o repositorio do laboratorio

    Todo o laboratorio (templates de Packer, preseeds, Autounattend.xml, scripts de configuración e os scripts build-all.sh / import.sh) está en ricardofc/viper-he.lab. Clónao:

    git clone https://github.com/ricardofc/viper-he.lab.git
cd viper-he.lab

    A estrutura que atoparás é:

    viper-he.lab/
├── build-all.sh            # Windows aparte + Debian en paralelo (+ limpeza previa)
├── import.sh               # importa os OVF e cablea a rede automaticamente
├── vm1-viper-c2/           # Debian 13 · C2/VIPER · .100
│   ├── debian13.pkr.hcl
│   ├── http/preseed.cfg
│   └── configure.sh        # instala Docker + VIPER + tuning + IP estática
├── vm2-victima-debian/     # Debian 13 · vítima payload · .101
│   ├── debian13.pkr.hcl
│   ├── http/preseed.cfg
│   └── configure.sh        # utilidades + usuario losada + IP estática
└── vm3-victima-win11/      # Windows 11 Eval · vítima mov. lateral · .102
    ├── windows11.pkr.hcl
    ├── Autounattend.xml     # instalación desatendida (BIOS/MBR + bypass TPM)
    ├── configure.ps1        # prepara a vítima (firewall/UAC/Defender off, SMB, IP)
    └── isos/                # aquí vai o teu windows11.iso (ver Paso 3)

    Paso 3 — Descargar as imaxes oficiais

    • Debian 13 netinst: báixao Packer automaticamente dende cdimage.debian.org; o SHA256 vai fixado no template, non hai que facer nada.
    • Windows 11 Enterprise Evaluation (es-ES): descárgao do Microsoft Evaluation Center e garda o ISO como vm3-victima-win11/isos/windows11.iso. Non fai falta pegar o SHA256: o build-all.sh xera automaticamente isos/SHA256SUMS co sha256 do teu ISO e o template verifícao.

    Paso 4 — Construír as imaxes

    A forma recomendada é o script build-all.sh, que limpa restos de builds anteriores, constrúe a Windows 11 aparte e despois as dúas Debian en paralelo (compartindo a caché do ISO):

    cd viper-he.lab
chmod +x build-all.sh import.sh
./build-all.sh

    Se prefires facelo a man, máquina por máquina:

    # VM-3 (Windows 11) — offline, autoxestionada (BIOS/MBR + bypass TPM)
cd vm3-victima-win11
( cd isos && sha256sum *.iso > SHA256SUMS )   # xera o checksum automaticamente
packer init . && packer build .

# VM-1 e VM-2 (Debian) — en paralelo, compartindo a caché do ISO
cd ..
export PACKER_CACHE_DIR=~/.packer_cache
( cd vm1-viper-c2       && packer init . && packer build . ) &
( cd vm2-victima-debian && packer init . && packer build . ) &
wait

    Cada build deixa a súa VM en output-autogenerated_1/ (*.ovf + *.vmdk).

    Paso 5 — Importar e cablear a rede

    As IPs van baked (estáticas dentro de cada SO). O único que o formato OVF non conserva ao importar é o modo de conexión dos adaptadores (NAT / rede interna); diso encárgase import.sh:

    ./import.sh

    Importa os tres OVF e deixa a rede xa cableada:

    VM Adaptador 1 Adaptador 2 IP interna
    VIPER-C2-ATACANTE NAT Rede interna viper-lan 192.168.120.100
    VIPER-VICTIMA-DEBIAN NAT Rede interna viper-lan 192.168.120.101
    VIPER-WIN11-VICTIMA Rede interna viper-lan — 192.168.120.102

    Arrinca as tres e xa está (non hai que tocar a rede a man). A VM-3 constrúese en BIOS/MBR (o Autounattend leva os bypass de TPM/SecureBoot), así que non fai falta activar EFI nin TPM.

    Paso 6 — Acceso e primeiro arranque

    • VM-1 (C2/VIPER): o escritorio XFCE arranca con autologin (viper / abc123.). VIPER corre en Docker con restart: always, así que arranca só en cada inicio; a primeira vez tarda uns minutos en estar listo o dashboard en https://192.168.120.100:60000 (root / abc123.). Hai un atallo VIPER Dashboard no escritorio.
    • VM-2 (vítima Debian): losada / abc123. (ou root / abc123.). É o obxectivo da reverse shell.
    • VM-3 (vítima Windows 11): autologin como usuario / abc123. (admin local). É o obxectivo do movemento lateral (psexec/SMB).

    Windows 11: paso manual obrigatorio antes do psexec

    Nun Windows 11 cliente non se pode desactivar Defender de forma fiable por script: antes hai que apagar a Protección contra manipulacións (Tamper Protection), que non é scriptable. Unha exclusión de ruta (C:\) NON abonda — o que importa é desactivar a protección en tempo real. Na VM-3, a man:

    1. Seguridad de Windows → Protección antivirus y contra amenazas → Administrar la configuración.
    2. Desactiva «Protección contra manipulaciones».
    3. Desactiva «Protección en tiempo real».
    4. Comproba: Get-MpComputerStatus | Select RealTimeProtectionEnabled, IsTamperProtected (debe ser RealTimeProtectionEnabled = False).

    Sen isto, o binario de servizo do psexec acaba en corentena e o ataque falla con «service failed to start – access denied».

    Os comandos concretos do ataque (reverse shell, movemento lateral e persistencia) están na práctica e nos apuntamentos de Metasploit.
